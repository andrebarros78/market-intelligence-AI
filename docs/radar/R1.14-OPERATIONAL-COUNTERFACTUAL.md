# R1.14 — Contrafactual Operacional

## Objetivo

Estimar o comportamento operacional esperado de uma entidade a partir de controles comparáveis selecionados apenas pelo histórico anterior, e medir a divergência entre esse caminho esperado e o valor realmente observado.

A R1.14 não implementa contrafactual causal. Ela produz uma referência operacional auditável para responder: **o alvo se comportou de forma materialmente diferente do grupo comparável?**

## Dependências concluídas

- R1.9 — comparação relacional/grupos de controle;
- R1.10 — resíduo não explicado;
- R1.11 — referência temporal/sazonal timestampada;
- R1.12 — seleção automática de controles sem usar o valor atual;
- R1.13 — atribuição automática de fatores observáveis sem declaração causal.

## Método V1

Para cada métrica candidata:

1. exigir histórico mínimo do alvo;
2. selecionar controles pelo `AutomaticControlSelector` usando somente histórico anterior;
3. exigir pelo menos três controles qualificados;
4. normalizar o movimento atual de cada controle pela sua própria escala histórica robusta;
5. exigir consistência suficiente do grupo;
6. calcular a mediana do sinal atual dos controles;
7. projetar esse sinal na escala histórica do alvo;
8. obter `counterfactual_expected`;
9. comparar o observado com a expectativa operacional;
10. emitir inferência apenas quando o gap ultrapassar os limiares de sinal e proporção.

Forma conceitual:

```text
control_signal_i = (control_current_i - control_baseline_i) / control_scale_i
expected_target = target_baseline + median(control_signal_i) * target_scale
counterfactual_gap = observed_target - expected_target
```

## Segurança epistemológica

A saída deve registrar explicitamente:

- `EvidenceLevel.INFERENCE`;
- `counterfactual_kind = operational_not_causal`;
- `causal_claim = false`;
- seleção de controles não usa valores atuais;
- estimação usa o movimento atual dos controles;
- valor atual do alvo não participa do ajuste da expectativa;
- a divergência não prova punição, intenção, algoritmo interno ou causalidade.

O campo legado/capability `counterfactual` continuará significando **contrafactual causal completo** e deve permanecer `false`. A nova capacidade será exposta separadamente como `operational_counterfactual`.

## Gates contra falso positivo

Não produzir resultado quando:

- histórico do alvo for insuficiente;
- houver menos de três controles qualificados;
- os controles forem historicamente pouco semelhantes;
- o grupo atual estiver disperso demais;
- a consistência do grupo for insuficiente;
- o gap for pequeno em escala histórica;
- o gap for pequeno em relação ao nível operacional esperado.

## Evidência obrigatória para conclusão

- testes unitários do estimador;
- invariância da expectativa ao valor atual do alvo;
- rejeição de grupo inconsistente ou insuficiente;
- integração no `build_default_radar()`;
- caminho HTTP `/v1/radar/evaluate`;
- caminho `RadarActivities`/Temporal;
- persistência PostgreSQL da evidência e deduplicação;
- capabilities honestas;
- migrations/drift/rollback sem regressão;
- CI completo verde no PR;
- CI pós-merge verde no `main`.
